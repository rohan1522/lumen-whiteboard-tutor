# 05 — Submission guidelines

Submit all three items below.

## 1. GitHub repository

Provide a repository URL containing the source code needed to understand your submission. Include a README that explains:

- The product idea, intended learner, and problem you chose.
- The main experience and how a reviewer can explore it.
- The technology stack and important architectural or product decisions.
- Local setup and run instructions, where practical.
- Required environment variables, using placeholder names and example values only (never publish real secrets).
- Which AI capabilities are live, mocked, sample-based, prerecorded, or simulated.
- Known limitations, incomplete areas, and what you would improve next.

You may include diagrams, screenshots, a short walkthrough, or other supporting material if they help communicate your work.

## 2. Live demo

Provide a public demo URL that reviewers can use to explore the working experience. If public access is not possible, explain the access requirements clearly in your submission. Do not expose credentials or private information in order to make the demo accessible.

## 3. Submission form

Complete the official Braynix Studios form:

[Open the assignment submission form](https://docs.google.com/forms/d/e/1FAIpQLSdFJoTxMEuFZrCHTbEgv7bbg2uLf33SjP7n0w2qUONR4kMRcA/viewform?usp=publish-editor)

Check that the repository and demo links are correct before submitting.

## Final review checklist

- [ ] Repository URL opens and contains the submitted project.
- [ ] README explains the idea and how to review it.
- [ ] Demo URL opens and the main experience can be explored.
- [ ] Live and simulated behaviour are clearly identified.
- [ ] No secrets or sensitive learner data are exposed.
- [ ] Submission form is completed.
